# 有线设备接入示例（摄像头实测经验）

> 本文前半部分适用于任意标准以太网设备，后半部分记录一款海思方案 IPC 摄像头模组的实测经验。
> 摄像头模组的具体参数、SDK 与固件资料请以**实际供货厂商的文档为准**。

## 一、通用接入规则

- 同一时间只接入一台有线客户端；
- DHCP 设备直接接入，由上游路由器分配地址；
- 静态 IP 设备必须使用与上游路由器相同的网段、掩码和网关；
- 网桥不提供 PoE，外设有源设备必须独立供电；
- 直连更换设备时，链路断开会自动清空旧 MAC；通过交换机更换且链路不断开时，重启网桥。

## 二、已验证的摄像头特征

| 项目 | 情况 |
|------|------|
| 方案 | 海思 HI3516CV610 |
| 无线能力 | **无 WiFi**（规格标注 N/A）——这是必须使用外置网桥的原因 |
| 有线网口 | 100BASE-TX（百兆），RJ45 |
| 供电 | **DC 12V / 2A**（≤2W 级功耗，但绝不能用网线 POE 取电，网桥不提供 POE） |
| 调试 | telnet（23 端口，busybox shell），RTMP 推流输出 |
| IP 方式 | 静态 IP（出厂默认地址多为 192.168.1.x 段，**接入前必须改到与路由器同网段**） |

## 三、摄像头接入五步法（实测流程）

1. **独立供电**：给模组接 12V 电源，确认网口指示灯与网桥侧 Link Up；
   > 实测教训：模组若依赖 POE 取电，接在网桥上会表现为"无法识别以太网口"——其实根本没上电。
2. **改静态 IP**：电脑直连模组（电脑临时设同网段静态 IP），telnet 进板子把 IP 改到路由器网段
   （建议选 DHCP 池之外的地址，如 .50~.99，避免租约冲突），**网关指向路由器**；
3. **改完重启模组**，确认配置已保存生效（telnet 里 `ifconfig` 核对）；
4. 网线改接**网桥**；直连插拔会触发链路断开，网桥会清空旧客户端并自动学习新设备 MAC；
5. 验证：从同一 WiFi 的电脑
   ```powershell
   ping <模组IP>          # 期望 TTL=64、延迟 >1ms（TTL=128/0ms 是自己应答自己）
   Test-NetConnection <模组IP> -Port 23
   telnet <模组IP>        # 进海思 shell
   ```
   同时网桥串口应打印 `Wired client MAC learned: xx:xx:...`。

## 四、RTMP 推流与控制

- 模组向平台发起 RTMP 推流（模组为 TCP 客户端，走"上行"方向，网桥对该方向完全透明）；
- **延迟参考**：直连路由器 ~300ms；经网桥+两跳同频 WiFi 后会明显增大。压延迟三板斧：
  1. **码率压到 2~3 Mbps 以内**（两跳空口有效容量有限）；
  2. **双频分流**：监控端/手机连路由器 5G，让 2.4G 只跑"模组→网桥→路由器"一段；
  3. 观察网桥串口的 `WiFi TX drop #N` 计数——持续增长说明空口拥塞，延迟只会更高；
- 控制指令建议走**独立轻量通道**（如 MQTT），不要与视频共用连接。

## 五、常见坑（实测踩过）

| 现象 | 原因 | 解法 |
|------|------|------|
| "无法识别以太网口" | 模组没独立供电（POE 假设落空） | 加 12V 电源 |
| ping 通但 TTL=128、0ms | 电脑自己的静态 IP 与模组目标 IP 相同，自己应答自己 | 电脑改回 DHCP，`arp -d *` 重测 |
| 模组改了 IP 但连不上 | 配置未保存/未重启生效 | telnet 里 `ifconfig` 核对，断电重启模组 |
| 通过交换机换接设备后新设备不通 | 交换机链路未断开，网桥仍保持第一个客户端 MAC | 断开网桥上行链路后重试，或重启网桥 |
| IP 配对但 ping 不通 | 目标网段与路由器不一致（出厂 192.168.1.x 遗留） | 按"接入五步法"第 2 步重做 |

## 六、给模组厂商/选型者的建议

- 采购时确认：是否支持 DHCP（若支持，可省去静态 IP 配置环节）、默认 IP 网段、telnet/SSH 凭据、
  RTMP 推流参数（分辨率/码率/GOP）的开放程度；
- 与本网桥配合的**最小要求**只有一个：模组有一个普通百兆以太网口，并使用标准 TCP/IP 栈——
  网桥在 L2 工作，对上层协议无任何要求。
